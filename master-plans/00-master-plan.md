# How master plans work

Read this file first. Then find every other master plan that could touch what
you are about to do, and read each one in full before you start.

## What a master plan is

A master plan is a short, human-dictated description of how we get from where we
are to where we want to be: the big picture, the ordered steps, and the criteria
that decide whether a step is done. It is the product's intent.

It is not a task list, not a design document, and not a record of what the code
currently does. A plan describes the destination; the code is only our latest
attempt to reach it.

## Reading them

- This file comes first, always.
- Then find the plans relevant to your work. Files are numbered in the order
  they were written; the number is not a priority.
- Read a relevant plan completely. A plan is one argument, and half of it will
  mislead you.
- A master plan outranks conclusions you draw from the existing code. When the
  two disagree, the code is what is wrong.
- If your work contradicts a plan, say so to the user and stop. Do not quietly
  adjust the plan to match what you built.

## Changing them

These documents belong to the user. They are dictated, not derived.

- Never create, rename, delete, or edit a master plan on your own initiative —
  including while cleaning up, reorganizing, or keeping documentation in sync.
- Edit one only when the user asks for that change in the current task, and
  change only what was asked.
- Write down what the user actually said. Do not soften it, do not add plans of
  your own, and do not invent detail to fill a gap. If the dictation is
  ambiguous, ask.
- Only an agent running on a top-tier model may write here — Claude Fable, or
  the latest GPT model at extra-high reasoning effort. A small or fast model
  must not edit a master plan, even under direct instruction; it should hand
  the request back to the user.

## Writing them

Keep a plan short enough to hold in your head. Say where we are going, the few
ordered steps to get there, and how we will know each one is finished. Prefer
plain sentences over elaborate structure. Leave out anything that will be
obsolete in a month.
